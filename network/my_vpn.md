# Tailscale接続記録

Tailscaleは、WireGuardを利用して端末同士を暗号化された仮想ネットワークへ接続するサービスである。Tailscaleによって作成されるプライベートネットワークを「Tailnet」と呼ぶ。

同じGoogleアカウントで認証した自宅サーバー、PC、スマートフォンは、同じTailnetへ参加する。各端末には、Tailscaleから固有のIPアドレスと端末名が自動的に割り当てられる。

今回の自宅サーバーでは、次の情報が確認できた。

```text
ホスト名: m75q-server
LAN側IPアドレス: 192.168.1.11
Tailscale IPアドレス: 100.93.62.95
```

## Tailscaleの接続

外出先から端末名を使ってSSH接続する場合は、次のコマンドを実行する。

```bash
ssh sugit@m75q-server
```

Tailscale IPアドレスを直接指定する場合は、次のように接続する。

```bash
ssh sugit@100.93.62.95
```

自宅サーバーでTailscaleのIPアドレスを確認する場合は、次のコマンドを実行する。

```bash
tailscale ip -4
```

Tailnetに参加している端末と接続状態を確認する場合は、次のコマンドを実行する。

```bash
tailscale status
```

外出先端末から自宅サーバーまでの接続経路を確認する場合は、次のコマンドを実行する。

```bash
tailscale ping m75q-server
```

実行結果に `DERP` と表示された場合は、DERP中継サーバーを経由している。

```text
via DERP(tok)
```

このSSH通信は、外側をTailscaleのWireGuardトンネル、内側をSSHによって暗号化される。

Tailscaleは、自宅サーバーまでの安全な通信経路を作る。ただし、SSHサービス自体は別途Ubuntuへ導入し、起動しておく必要がある。

Tailscaleは、WireGuardによる暗号化に加えて、次の機能を自動化している。

- 端末認証
- 公開鍵の配布
- NAT越え
- 接続経路の探索
- DERPによる中継
- MagicDNS
- アクセス制御

この自動化によって、ホームゲートウェイでポート開放できない環境でも、自宅サーバーへ接続できる。

## Tailscaleの設定手順

1. Googleアカウントを使ってTailscaleにログインする
2. `Personal use` など、利用目的を選択する
3. 自宅サーバー、PC、スマートフォンを同じGoogleアカウントで認証する

## 他のやり方での接続

### 1. XG-100NE内蔵VPNサーバー

XG-100NEの公式ガイドには、L2TP/IPsec VPNサーバー機能が記載されている。

ただし、公式にも、契約によってVPNサーバー設定画面が表示されない場合があると明記されている。

実際の管理画面では「VPNサーバー設定」が表示されなかった。このため、現在の契約・提供構成では、XG-100NE本体をL2TP/IPsec VPNサーバーとして設定できないと判断した。

### 2. UbuntuをWireGuardサーバーにする

次の構成を検討した。

```text
外出先PC
  ↓ UDP 51820
XG-100NE
  ↓ 静的IPマスカレード（ポート転送）
Ubuntu 192.168.1.11
```

この方式では、少なくとも以下の条件が必要になる。

1. 自宅側で、外部から到達可能なグローバルIPv4を使用できること
2. XG-100NEで、UDP `51820`を`192.168.1.11`へ転送できること
3. Ubuntu上でWireGuardが待ち受けていること
4. 動的IPv4の場合は、現在のIPアドレスを確認する手段、またはDDNSがあること

しかし、確認したXG-100NEの管理画面では「静的IPマスカレード設定」が表示されなかった。

また、「現在の状態」にPPPoEメインセッションの接続状態や、WAN側のIPv4アドレスが表示されなかった。

画面に表示されたWANの「通信中（10Gbps 全二重）」は物理的なリンク状態であり、グローバルIPv4を持っていることを意味しない。

これらを合わせると、現在はIPoEが中心の接続であり、一般的なIPv4ポート転送を利用できない可能性が高い。

そのため、WireGuard自体の設定に失敗したわけではない。現在の回線・ホームゲートウェイ構成では、IPv4で自宅のWireGuardサーバーへ着信させるための前提条件を確認できなかったため、作業を止めた。

## 補足

### L2TP

インターネットなどの公共ネットワーク上に、仮想的な通信トンネルを作るためのプロトコル。

L2TP自体には通信を暗号化する機能がないため、通常はIPsecと組み合わせて利用する。

### IPsec

IPネットワーク上でデータの暗号化や通信相手の認証を行い、安全な通信を実現するための仕組み。

### 静的IPマスカレード

外部から特定のポート番号へ届いた通信を、LAN内の指定した端末とポートへ転送する機能。

今回の構成では、外部からUDP `51820`へ届いた通信を、Ubuntuの`192.168.1.11:51820`へ転送するために必要となる。

### PPPoE

ルーターがプロバイダーへユーザー名とパスワードを使って接続し、IPv4接続を作る従来型の方式。

### IPoE

PPPoEのような接続操作を行わず、主にIPv6網を利用してインターネットへ接続する新しい方式。

PPPoEより高速で混雑しにくい一方、プロバイダーの提供方式によっては、利用者が自由にIPv4のポート転送を設定できない場合がある。
