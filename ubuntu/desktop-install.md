# Ubuntu Desktopのインストール記録

## 1. インストール対象

- **OS**: Ubuntu Desktop 26.04.1 LTS

---

## 2. 使用環境

- **CPU**: AMD Ryzen 5 PRO 3400GE with Radeon Vega Graphics
- **RAM**: 16 GB
- **SSD**: 128 GB（SAMSUNG MZALQ128HBHQ-000L1）
- **Network**: 有線LAN
- **PC**: Lenovo ThinkCentre M75q-1

---

## 3. インストール手順

### 3.1 Ubuntu DesktopのインストールUSBを作成する

[Ubuntu公式サイト](https://jp.ubuntu.com/download)から、Ubuntu DesktopのISOファイルをダウンロードする。

Windowsでは、Rufusなどのツールを使用してISOファイルをUSBメモリへ書き込む。

#### ISOファイルについて

ISOファイルは、OSのインストールに必要なファイルを1つにまとめたディスクイメージである。

ISOファイルを通常のファイルとしてUSBメモリへコピーするだけでは、原則としてインストールUSBにはならない。

Rufusなどのツールを使用して、USBメモリからPCを起動できる状態にする必要がある。

> USBメモリへの書き込みを実行すると、USBメモリ内の既存データは削除されるため、必要なデータは事前に退避する。

---

### 3.2 BIOS / UEFIを確認する

BIOS / UEFI設定画面は、PCの電源を入れた直後に `F1` を連打することで開くことができる。

#### 確認項目

- **Boot Mode**  
  `Startup -> Boot Mode` を確認し、`UEFI Only` であることを確認した。

- **Secure Boot**  
  `Enabled` であることを確認した。

- **SSD**  
  `SAMSUNG MZALQ128HBHQ-000L1` が認識されていることを確認した。

- **USB Boot**  
  `Startup -> Primary Boot Sequence` に `USB HDD` が存在することを確認した。

- **Storage Mode**  
  `Configure SATA as` が `AHCI` であることを確認した。

#### UEFIについて

UEFIは、PCの電源を入れた直後に動作し、主に以下の処理を行う仕組みである。

- CPUやメモリなどのハードウェアの初期化
- SSDやUSBメモリなどの起動デバイスの検出
- 使用する起動デバイスの決定
- OSの起動処理への引き渡し

従来のBIOSの後継にあたる仕組みで、現在のPCではUEFIが一般的に使用されている。

#### Secure Bootについて

Secure Bootは、信頼された電子署名を持つソフトウェアだけを起動できるようにするUEFIのセキュリティ機能である。

UbuntuはSecure Bootに対応しているため、今回は有効のまま使用した。

一部の追加ドライバーを導入した場合は、初回起動時にドライバーを許可するための操作が必要になることがある。

#### Storage Modeについて

Storage Modeは `AHCI` であることを確認した。

AHCIは、SATA接続のストレージをOSから制御するための一般的な方式であり、Linuxでも広く利用されている。

今回はUbuntu Desktopからストレージを正常に認識できるため、設定を変更せずに使用した。

---

### 3.3 USBからUbuntu Desktopを起動する

Boot Menuは、PCの電源を入れた直後に `F12` を連打することで開くことができる。

Boot Menuでは以下を確認した。

- USBメモリが `USB HDD: Generic Mass Storage` として認識されている
- UEFI起動用の `UEFI: Generic Mass Storage ...` が表示されている
- 内蔵M.2 SSD `SAMSUNG MZALQ128HBHQ-000L1` が認識されている

Ubuntu Desktopは、USBメモリのUEFI起動項目を選択して起動した。

起動後、Ubuntuのインストーラーを開始した。

USBメモリから起動した段階では、まだ内蔵SSDへのインストールは開始されていない。

実際にSSDのパーティション構成を確定し、インストールの開始を承認するまでは、内蔵SSDの内容は変更されない。

---

### 3.4 Ubuntu Desktopの初期設定

インストーラーはGUIで表示され、画面の指示に従って設定した。

GUIは「Graphical User Interface」の略で、文字だけでなく、ウィンドウ、ボタン、メニューなどを使って操作する画面である。

#### 設定内容

| 項目 | 設定 |
|---|---|
| 使用言語 | 日本語 |
| Keyboard Layout | Japanese |
| Keyboard Variant | Japanese |
| Network | 有線LAN |
| 実行する操作 | Ubuntuをインストール |
| インストール方式 | 対話的インストール |
| アプリケーション | 既定の選択 |
| プロプライエタリなソフトウェア | インストールしない |
| ディスクの使用方法 | ディスクを削除してUbuntuをインストール |
| Installation target | `SAMSUNG MZALQ128HBHQ-000L1` |
| ディスク暗号化 | 使用しない |
| ファイルシステム | インストーラーの既定設定 |
| タイムゾーン | `Asia/Tokyo` |
| OpenSSH Server | インストール後に必要に応じて導入 |

---

#### 使用言語

インストーラーおよびUbuntu Desktopの表示言語として、日本語を選択した。

Ubuntu Desktopのメニュー、設定画面、通知などは、基本的に日本語で表示される。

一方、ターミナルに表示されるコマンド名、ファイル名、ログなどは英語で表示されることがある。

---

#### Keyboard Layout / Variant

- **Layout**: Japanese
- **Variant**: Japanese

Layoutは、国や地域ごとの基本的なキーボード配列を指定する。

Variantは、そのLayout内に存在する細かな配列の違いを指定する。

今回は日本語JISキーボードを使用しているため、両方とも `Japanese` を選択した。

インストール画面に文字入力欄がある場合は、以下のキーを確認しておく。

```text
@
:
[
]
\
_
```

期待した記号が入力されない場合は、キーボードレイアウトが実際のキーボードと一致していない可能性がある。

---

#### Network

有線LANを使用してインターネットへ接続した。

有線LANでは、通常はルーターのDHCP機能により、以下の情報が自動的に設定される。

- IPアドレス
- サブネット
- デフォルトゲートウェイ
- DNSサーバー

DHCPは、ネットワークに接続した端末へIPアドレスなどの設定を自動配布する仕組みである。

インストール時にネットワークへ接続すると、更新情報や追加パッケージを取得できる。

ネットワークへ接続できない場合でもインストールを続けられる場合があり、更新はインストール完了後に実行できる。

---

#### Ubuntuで行う操作

`Ubuntuをインストール` を選択した。

インストーラーのバージョンによっては、Ubuntuを試用する選択肢が表示される場合がある。

試用環境では、内蔵SSDへインストールせずに、USBメモリからUbuntu Desktopを起動できる。

試用環境は、以下を事前に確認する場合に利用できる。

- 画面表示
- 有線LAN
- Wi-Fi
- キーボード
- マウス
- 音声
- 内蔵SSDの認識

---

#### インストール方式

`対話的インストール` を選択した。

対話的インストールでは、言語、キーボード、ストレージ、ユーザー情報などを画面上で順番に設定する。

ほかに、設定ファイルを使用する自動インストールや、Landscapeを使用した集中管理のための選択肢が表示される場合がある。

- **自動インストール**  
  あらかじめ用意した設定ファイルを使用して、複数の設定を自動化する方式。

- **Landscape**  
  Canonicalが提供するUbuntu端末の管理サービス。複数台のUbuntuを一元管理する用途で利用される。

今回は1台のPCへ手動でインストールするため、対話的インストールを選択した。

---

#### アプリケーションの選択

`既定の選択` を選択した。

既定の選択では、Webブラウザと基本的なユーティリティを中心としたUbuntu Desktop環境がインストールされる。

追加のアプリケーションが必要になった場合は、インストール完了後にUbuntu App CenterやAPTを使用して導入できる。

- **ユーティリティ**  
  システム設定、ファイル管理、圧縮・展開など、基本的な操作に使用するソフトウェア。

- **APT**  
  Ubuntuでソフトウェアの検索、インストール、更新、削除を行うパッケージ管理システム。

---

#### プロプライエタリなソフトウェア

推奨されるプロプライエタリなソフトウェアは、インストールしなかった。

プロプライエタリなソフトウェアとは、ソースコードや利用条件が開発元によって制限されているソフトウェアである。

対象には以下が含まれる場合がある。

- 一部のグラフィックドライバー
- 一部のWi-Fiドライバー
- 動画や音声を再生するためのコーデック
- ハードウェアメーカーが提供する追加ソフトウェア

今回は基本構成を確認するため、インストール時には追加しなかった。

必要になった場合は、インストール完了後に導入する。

---

#### ディスクの使用方法

`ディスクを削除してUbuntuをインストール` を選択した。

インストール対象として、以下のSSDを選択した。

```text
SAMSUNG MZALQ128HBHQ-000L1
```

この方式では、SSD上の既存パーティションとデータが削除され、SSD全体がUbuntu Desktop用として再構成される。

インストーラーにより、OSの起動と動作に必要な領域が自動的に作成される。

例：

- EFIシステムパーティション
- ルートファイルシステム `/`
- 必要に応じたスワップ領域

> 「ディスクを削除してUbuntuをインストール」を確定すると、対象SSDに保存されているWindows、Ubuntu、個人ファイルなどは削除される。実行前に、対象SSDの型番と必要なバックアップを確認する。

#### パーティションについて

パーティションは、1台のSSDを用途ごとの領域に分ける仕組みである。

ルートディレクトリ `/` は、Ubuntuのシステムファイル、アプリケーション、ユーザーデータなどが配置されるファイルシステムの起点である。

EFIシステムパーティションには、UEFIがOSを起動するために使用するブートローダーが保存される。

---

#### 暗号化とファイルシステム

ディスク暗号化は使用しなかった。

ディスク暗号化を有効にすると、SSDをPCから取り外して別のPCへ接続された場合でも、パスフレーズを知らない第三者によるデータの読み取りを防止できる。

一方、暗号化方式によっては、PCの起動時に毎回パスフレーズの入力が必要になる。

パスフレーズを紛失するとデータを復旧できなくなる可能性があるため、安全な場所で管理する必要がある。

今回はインストール練習と基本環境の確認を目的としているため、暗号化は使用しなかった。

ファイルシステムはインストーラーの既定設定を使用した。

ファイルシステムは、SSD上でファイルやディレクトリを保存・管理する仕組みである。Ubuntuでは一般的に `ext4` が使用される。

---

#### ユーザー名とパスワード

以下の情報を設定した。

- 表示名
- コンピューター名
- ユーザー名
- ログインパスワード

実際のパスワードはインストール記録やGitHubへ記載しない。

ユーザー名は、ホームディレクトリの名前などに使用される。

例：

```text
/home/ユーザー名
```

コンピューター名は、ネットワーク上でPCを識別するための名前として使用される。

例：

```text
ubuntu-desktop
```

パスワードには、推測されにくく、ほかのサービスで使用していないものを設定する。

---

#### 現在地とタイムゾーン

現在地として東京を指定し、タイムゾーンを以下に設定した。

```text
Asia/Tokyo
```

タイムゾーンは、システム上の日時、ログ、ファイルの更新時刻などを地域の時刻へ変換するための設定である。

---

### 3.5 インストールを開始する

設定内容の確認画面で、以下を確認した。

- インストール対象がUbuntu Desktopである
- インストール対象SSDが正しい
- ディスク全体を使用する設定になっている
- ディスク暗号化が無効になっている
- ユーザー名とコンピューター名が正しい
- タイムゾーンが `Asia/Tokyo` になっている

内容を確認した後、インストールを開始した。

インストール完了後に再起動し、画面の指示に従ってUSBメモリを取り外した。

再起動後、内蔵SSDからUbuntu Desktopが起動することを確認した。
