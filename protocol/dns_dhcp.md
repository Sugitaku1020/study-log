# DNS(Domain Name System)
## 概要
インターネット上で、ドメイン名(英字・数字・ハイフンで構成された各部分を、ピリオドで区切る)とIPアドレスの対応関係を管理するシステム. 利用者は単なる番号であるIPアドレスではなく、日常使っている言語の文字を組み合わせた認識しやすいドメイン名でネットワーク上の資源にアクセスできるようにする。
このシステムはホストを管理している組織がデータの設定や変更を行うことができる. (ARPANETの時代はセンターで一元管理), つまり、組織内でホスト名とIPアドレスの関係を表すデータベースを管理できる.
通信したいユーザーがホスト名(およびドメイン名)を入力すると、自動的にホスト名やIPアドレスが登録されているデータベースサーバーが検索され、そこからIPアドレスの情報を得る.

## ドメイン名の構造
ドメイン名はホストの名前や組織の名前を識別するための階層的な名前のこと。
例) kusa.ac.jp (倉敷芸術科学大学)
複数の短い英字がピリオドによってつながれた構造を持っている. 
kusa: 倉敷芸術科学大学(Kurashiki Univiersity of Science and the Arts)固有のドメイン名
ac: 大学(academy)や高専、専門学校などの高等教育機関
jp: 日本(japan)
ドメイン名を使用した場合には、それぞれのホスト名の後に、その組織のドメイン名をつける.
pepper, piyo, kinokoというホスト名があったとき、以下のイメージ.
```
pepper.kusa.piyo.ac.jp
piyo.kusa.ac.jp
kinoko.kusa.piyo.ac.jp
```
(peppr: ホスト名、kusa.ac.jp: ドメイン名、pepper.kusa.ac.jp: 完全装飾ドメイン名(FQDN))

## DNSが管理する情報の補足
DNSはドメイン名とIPアドレスの対応関係だけでなく、メールの配送先や別名などの情報も管理する。これらの情報は、種類ごとに「リソースレコード」として登録される。

- Aレコード：ドメイン名に対応するIPv4アドレス。
- AAAAレコード：ドメイン名に対応するIPv6アドレス。
- CNAMEレコード：別名に対応する正式なドメイン名。
- MXレコード：メールの配送先となるサーバーのドメイン名。
- NSレコード：そのドメインのDNS情報を管理する権威DNSサーバーのドメイン名。

# DHCP(Dynamic Host Configuration Protocol)
## 背景
ホストごとにIPアドレスを設定するのは非常に面倒。特に、ラップトップ型のコンピュータやスマートフォン、タブレットPCを持ち歩くなど、1箇所に固定せずコンピュータを使う場合はなおさら。移動するたびにIPアドレスの変更をしなければならない。

## 概要
面倒なIPアドレスの設定を自動化したり、配布するIPアドレスの一括管理を行う通信規約をDHCPと呼ぶ.
これにより、コンピュータをネットワークに接続しただけでTCP/IPによる通信ができるようになる. IPv4だけでなくIPv6でも使用される.

DHCPサーバーに障害が発生すると困ったことにIPアドレスが配られなくなるため、セグメント内(ネットワーク内)のホストがすべて通信不能になってしまう。この問題を避けるために複数のDHCPサーバー起動することが奨励されている.
→ 一方のDHCPサーバーが割り当てたIPアドレスを別のDHCPサーバーが配布してしまう危険性.
対策は以下
- DHCPサーバー : :IPアドレスを配布する前にICMPエコー要求パケットを送信し、返事がこないことを確認する.
- DHCPクライアント : DHCPサーバーから配布されたIPアドレスに対してARP要求パケットを送信し、応答が来ないことを確認する.

処理に時間はかかるが安全性が向上する.

## DHCPリレーエージェント

別のネットワークにあるDHCPサーバーとの通信を中継する機能。

通常、パソコンはネットワークに接続すると、DHCPサーバーに「IPアドレスをください」と要求する。しかし、この要求は基本的に同じネットワーク内にしか届かない。

そこで、DHCPリレーエージェントが要求を受け取り、別のネットワークにあるDHCPサーバーへ届ける。

これにより、**ネットワークごとにDHCPサーバーを設置せず、1台のサーバーで複数のネットワークのIPアドレスを管理できる。**
